# 备用评审说明（cmedqa_judgments_fallback.jsonl）

## 为什么有备用评审

主评审 `deepseek-flash`（思考模式，输出上限 1024 token）在 290 对上思考过长、输出被截断，没有给出分数
（缓存里 raw 为"空输出 finish=length，有思考内容"）。这些对不是随机失败的，多是主评审难以下结论的样本，
直接按"不相关"处理会让补标结果系统性偏低，所以由备用评审补判。

## 怎么补的

- 评审：claude-opus-5-5（在对话中逐条阅读后打分），与主评审使用**同一份评分标准**（`rag/judge.py` 里的 JUDGE_PROMPT，v1），
  回答同样截断到 800 字；补判时看不到原标注是否为正例。
- 只填补主评审没给出分数的对；主评审有分数的一律以主评审为准。
- 共 290 对：第一批 239 对（2 分 102、1 分 108、0 分 29），主评审跑完后又补了 51 对（2 分 13、1 分 30、0 分 8）。

## 备用评审和主评审一致吗（校准）

从主评审已打分的对里按 0/1/2 各抽 20 对（共 60 对），备用评审在**看不到主评审分数**的情况下盲评，结果见
`cmedqa_fallback_calibration.jsonl`：

| 口径 | 一致率 | Cohen's kappa |
| --- | --- | --- |
| 三档（0/1/2） | 87% | 0.80 |
| 严格（≥2 算相关） | 95% | 0.89 |
| 宽松（≥1 算相关） | 92% | 0.81 |

混淆矩阵（行 = 主评审，列 = 备用评审）：0 → [16, 4, 0]；1 → [1, 18, 1]；2 → [0, 2, 18]。两者平均分 1.00 vs 1.03，没有明显的整体偏松或偏严。
因此失败样本里 2 分比例（43%）明显高于整体（约 12%），主要反映的是这批样本本身更相关（主评审在"1 还是 2"之间反复斟酌才超长），
而不是备用评审标准更宽。

## 局限

- 两个评审都是大模型，一致不代表正确；正确性要看人工盲评（`relabel.py agree`）。
- 备用评审的打分无法用脚本自动复现；报告里的"敏感性"一节给出了去掉这部分（按不相关处理）后的结果，用于判断结论是否依赖它。

## 补判时对"建议去医院 / 要求补充图片"类回答的处理

评分标准（v1）没有单独写这一类，补判和人工盲评统一按下面的口径，原则是"用户读完有没有得到和问题相关的有用信息"：

| 情况 | 分数 | 例子 |
| --- | --- | --- |
| 只有"去医院检查 / 请补充图片 / 请问你多大了"之类，没有任何针对性内容 | 0 | "最好到医院检查，排除疑虑" |
| 给了和问题相关的实质信息（可能原因、该做什么检查、挂哪个科），再建议就医 | 1 | "考虑是尿路感染，建议到医院查尿常规" |
| 就医本身就是问题的核心答案：急症/危险信号需要立刻就医，或用户问的就是"要不要去医院、挂什么科、做什么检查" | 2 | 孕 9 周无胎心问能否保住 → "需要医院复查确诊，确认无胎心只能终止妊娠" |
| 回答引用了看不到的图片，但正文给出了判断和处理 | 按正文内容打分 | "看图片像是肛周脓肿，带孩子到肛肠科检查" → 2 |

主评审的打分和这个口径基本一致：主评审打过分的回答里，≤45 字、以建议就医为主的有 149 条（1 分 108、0 分 22、2 分 19），
以要求图片为主的有 92 条（0 分 67、1 分 22、2 分 3）。
